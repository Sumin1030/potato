# 디자인 구현 프로세스

디자인 링크를 기반으로 UI를 구현할 때 적용한다.

## 1. 기존 자산 확인

구현 전에 디자인과 프로젝트를 비교하여 다음 항목을 확인한다.

- 디자인에 사용된 색상, 타이포그래피, 간격, radius, border, shadow
- `src/shared/styles`에 정의된 기존 디자인 토큰
- `src/shared`에 있는 기존 공통 컴포넌트
- 기존 컴포넌트의 variant, state, 반응형 동작
- 유사한 화면에서 같은 역할의 UI에 실제로 적용한 토큰과 컴포넌트 사용 방식

Figma 디자인과 프로젝트 토큰이 항상 일치한다고 가정하지 않는다. 디자인과 정확히 일치하는 토큰이 없으면 새 값을 바로 추가하거나 raw value를 사용하지 않고, 기존 공통 컴포넌트와 유사 페이지에서 같은 역할을 어떻게 구현했는지 먼저 확인한다.

프로젝트 안에서 이미 같은 의미로 사용 중인 표현이 있으면 코드의 일관성을 우선한다. 시각적 차이가 크지 않고 의미, 사용성, 접근성, 레이아웃에 무리가 없다면 Figma 값과 가장 가까운 기존 토큰과 컴포넌트를 사용한다.

## 2. 차이 분류

기존 토큰이나 공통 컴포넌트와 일치하지 않는 부분은 아래 두 종류로 나눈다.

### 기존 항목으로 대체 가능한 부분

시각적 차이가 작고 의미, 사용성, 접근성, 레이아웃에 영향을 주지 않는다면 가장 가까운 기존 토큰이나 컴포넌트로 대체하는 방향을 우선 제안한다.

각 항목에 다음 내용을 포함한다.

- 디자인 원본 값 또는 형태
- 대체할 기존 토큰 또는 컴포넌트
- 기존 프로젝트에서 해당 토큰 또는 컴포넌트를 사용 중인 위치
- Figma 원본에서 실제 코드로 변경되는 사항
- 예상되는 시각적 차이와 영향 범위
- 해당 변경으로 코드 사용 방식을 통일한 이유
- 대체해도 의미, 사용성, 접근성, 레이아웃에 무리가 없는 이유

### 새 항목이 필요한 부분

대체할 경우 의미나 상태가 달라지거나 시각적 차이가 분명해진다면 새 토큰 또는 공통 컴포넌트 추가를 제안한다.

토큰 제안에는 다음 내용을 포함한다.

- 토큰 이름
- 값
- semantic 역할
- 기존 토큰으로 대체할 수 없는 이유
- 예상 사용처

공통 컴포넌트 제안에는 다음 내용을 포함한다.

- 컴포넌트 이름과 책임
- 필요한 variant와 state
- 재사용이 예상되는 위치
- 기존 컴포넌트를 확장할지 새로 만들지
- 접근성과 반응형 동작에서 지켜야 할 사항

## 3. 구현 전 공유

차이가 발견되면 구현 전에 아래 형식으로 제안 사항을 공유한다. 해당 항목이 없으면 `없음`으로 표시한다.

```md
## 기존 항목 재사용
- ...

## 기존 항목으로 대체 제안
- Figma 원본: ...
- 적용 코드: ...
- 기존 사용 위치: ...
- 변경 사항: ... → ...
- 변경 이유와 영향: ...

## 새 토큰 추가 제안
- ...

## 공통 컴포넌트 추가 또는 확장 제안
- ...
```

사용자가 즉시 구현을 요청한 경우에는 제안 사항을 공유한 뒤 그 기준으로 계속 작업한다. 사용자의 선택이 결과를 크게 바꾸는 경우에는 구현 전에 방향을 확인한다.

## 4. 구현

- 확인된 기존 토큰과 공통 컴포넌트를 사용한다.
- 토큰 이름만 비교하지 않고 기존 공통 컴포넌트와 유사 페이지의 실제 사용 방식에 맞춰 코드를 통일한다.
- 합의되지 않은 임의의 raw color나 반복되는 magic number를 추가하지 않는다.
- 새 토큰과 공통 컴포넌트는 공유한 방향에 맞춰 추가한다.
- 디자인의 의도와 프로젝트의 기존 규칙이 충돌하면 프로젝트 규칙에 맞게 조정하고 그 차이를 알린다.

## 5. 구현 후 차이 보고

기존 토큰이나 컴포넌트에 맞추기 위해 Figma와 다르게 구현한 부분은 작업 결과에 빠짐없이 리스트업한다. 각 항목은 다음 형식으로 보고한다.

```md
- 대상: ...
  - Figma 원본: ...
  - 적용 코드: ...
  - 변경 사항: ... → ...
  - 변경 이유: 기존 공통 컴포넌트 또는 유사 페이지의 ... 사용 방식과 통일
  - 영향: ...
```

차이가 없으면 `Figma와 다르게 적용된 항목 없음`이라고 명시한다.
