# 기본 개발 규칙

프로젝트의 코드를 작성하거나 구조를 변경할 때 적용한다.

## 요청 범위 준수

- 사용자가 요청한 작업 범위 안에서만 변경한다.
- 작업자의 명시적인 지시 없이 Markdown(`.md`) 파일을 임의로 추가하거나 수정하지 않는다.
- 사용자의 요청대로 작업했을 때 문제가 생길 가능성이 있어도, 요청한 작업 자체는 우선 그대로 수행한다.
- 예상되는 문제는 숨기지 않고 작업 결과와 함께 원인과 영향 범위를 알린다.
- 예상되는 문제마다 현재 구조를 고려한 해결책을 함께 제시한다.
- 기능 구현 요청을 프로젝트 전체 설정 변경에 대한 허용으로 해석하지 않는다.
- 요청을 구현하는 과정에서 기존 구조나 프레임워크 설정과 충돌을 발견하면, 전역 설정을 임의로 변경하지 않는다.
- 요청 범위 안의 작업을 먼저 완료한 뒤, 충돌의 원인과 영향 범위 및 가능한 해결책을 알린다.
- 요청한 작업을 완료할 수 없거나 되돌리기 어려운 손상이 예상될 때만 작업 전에 방향을 확인한다.

## 전역 설정 변경

다음 항목은 사용자가 명시적으로 요청했거나 사전에 방향을 확인한 경우에만 변경한다.

- 프레임워크 설정
- 라우팅 규칙과 파일 규칙
- 빌드 및 배포 설정
- TypeScript, ESLint, Tailwind 설정
- 패키지 매니저와 런타임 버전
- 프로젝트 전체에 영향을 주는 경로 alias

작업을 위해 전역 설정 변경이 필요해 보여도, 기존 관례를 유지할 수 있는 대안을 먼저 찾는다.

## 프로젝트 관례 유지

- Next.js App Router의 특수 파일명과 기본 동작을 유지한다.
- FSD 레이어 이름이 프레임워크의 예약 디렉터리와 충돌하면 프레임워크 설정을 바꾸지 않고 레이어 이름을 조정하는 방향을 우선 제안한다.
- 기존 파일과 사용자의 변경 사항을 보존하고, 요청과 관련 없는 파일은 수정하지 않는다.
- 작업 중 발견한 기존 placeholder, metadata, 문구, 설정을 요청 없이 정리하거나 개선하지 않는다.
- 특정 화면 구현 요청은 layout, metadata, 전역 스타일, 설정 파일 변경을 허용하지 않는다. 해당 변경이 반드시 필요하면 요청한 작업을 먼저 완료하고, 변경이 필요한 이유와 해결책을 알린다.
- 새 구조나 추상화는 현재 필요한 범위까지만 추가한다.

## 환경변수

- 로컬 환경변수는 프로젝트 루트의 `.env.local`에서 관리하고 Git 추적 대상에서 제외한다.
- Supabase 연결에는 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 사용한다.
- 서버 전용 환경변수에는 `NEXT_PUBLIC_` 접두사를 붙이지 않는다.
- 실제 키를 소스 코드, 문서, 로그와 테스트 출력에 포함하지 않는다. 확인 시 설정 여부만 출력한다.
- 필수 환경변수는 해당 서버 기능을 실행할 때 검사한다.
- 환경변수 변경이 반영되지 않으면 개발 서버를 재시작한다.
- Vercel에서는 해당 배포 환경에 같은 변수명을 등록하고 변경 후 다시 배포한다.

## 검증

- 변경 범위에 맞는 lint, 타입 검사, 빌드 검증을 실행한다.
- 검증을 위해 제품 코드나 전역 설정을 임의로 변경하지 않는다.
- 발견한 문제 중 요청 범위 밖의 문제는 자동으로 수정하지 않고 사용자에게 알린다.
