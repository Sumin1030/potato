# 프로젝트 구조

Feature-Sliced Design(FSD)을 기반으로 구성하되, Next.js의 예약 디렉터리 `pages` 대신 화면 레이어 이름으로 `views`를 사용한다.

## 위치와 역할

```text
src/
├── app/                 # Next.js 라우트와 프레임워크 특수 파일
├── views/
│   └── <slice>/
│       ├── ui/          # 해당 화면의 페이지·컴포넌트
│       ├── api/         # 서버 조회·변경 함수
│       └── lib/         # 검증·변환·계산 등 보조 로직
└── shared/
    ├── ui/              # 공통 컴포넌트
    ├── lib/             # 공통 유틸리티와 서버 연결 기반 코드
    └── styles/          # 공통 스타일과 디자인 토큰
```

- `views`는 화면별 slice로 구분하고, 각 slice에 필요한 segment만 만든다.
- `shared`에는 별도 slice를 두지 않는다.
- 페이지 전용 코드와 하위 컴포넌트는 해당 slice에 둔다. 실제로 여러 화면에서 재사용할 필요가 확인된 경우에만 `shared`로 분리한다.
- 명시적인 요청 없이 `features`, `widgets`를 추가하거나 그곳으로 코드를 이동하지 않는다.
- `src/pages` 디렉터리는 만들지 않는다.

## 페이지 라우팅

- 새 페이지에는 대응하는 `src/app/<route>/page.tsx`를 만든다.
- 라우트 파일은 `views` 페이지 컴포넌트의 조립과 라우트 파라미터 전달을 담당한다. 화면 UI는 `ui`, DB 접근 코드는 `api`에 둔다.
- 페이지 생성 시 메뉴, 진입 버튼, 뒤로 가기 등 기본 이동 경로도 연결한다.
- 기존 URL 규칙을 따르며, 별도 규칙이 없으면 페이지 역할을 나타내는 kebab-case를 사용한다.

## 아이콘 에셋

- UI 아이콘은 `public/assets` 바로 아래에 둔다. 페이지·기능별 하위 디렉터리를 미리 만들지 않는다.
- 아이콘이 많아져 분류가 필요하면 기준과 변경 경로를 먼저 제안한다.
- `src/app/favicon.ico`, `src/app/icon.png` 등 Next.js 특수 메타데이터 파일은 이 규칙에서 제외한다.
